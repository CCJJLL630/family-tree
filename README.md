# 枝 · 家谱

一个中文家谱网页。用来记录家人资料、查看家族关系，以及在走亲戚时查询称呼。数据保存在本机浏览器或自选文件夹，不发送到外部服务器；称呼推导也完全在本机完成。

## 启动

需要 Node.js 22 或更新版本。在 PowerShell 中运行：

```powershell
Set-Location D:\CjlFile\family-tree
npm.cmd ci --ignore-scripts --no-audit --no-fund
node server.js
```

打开 **http://127.0.0.1:4173**。按 `Ctrl+C` 停止服务。

安装依赖后，也可以在 VS Code 中打开本项目目录，运行“家谱：启动本机网页”任务。项目没有构建步骤。依赖只需首次安装或更新锁文件后重装，之后启动与查询不需要联网。

如果端口被占用：

```powershell
$env:PORT = '4174'
node server.js
```

**尚未设置文件夹时，请保持相同的网址和端口。** `localhost`、`127.0.0.1`、不同端口和不同浏览器各有独立的浏览器数据。设置文件夹后，同一项目服务使用共同的文件存档，其他浏览器的旧副本不会自动合并。

当前启动器只监听本机，不开放局域网端口。页面适配手机尺寸，但手机不能通过自己的 `127.0.0.1` 访问电脑。本版本需要配套的本机 Node 服务，不支持只部署静态页面，也没有远程访问的登录和权限系统；不要把服务暴露到公网。

## 使用

1. 在上方家谱标签中选择要编辑的家谱。点击家谱展示区顶部、家谱名称旁的“添加成员”，先录入自己或一位长辈；不确定的信息可以留空。
2. 录入其他成员。在子女的编辑窗口中选择父母，指定亲生、收养或继亲。只建立配偶关系不会自动创建父母关系。
3. 在“我是谁”中选择本人，或在人物资料中点击“设为本人”。
4. 在成员列表中搜索姓名、小名、备注或城市，点击人物查看资料。家谱节点也可以点击，并支持键盘 Tab、Enter 和空格。
5. 在称呼查询区域选择两人，查看双向称呼及关系路径。点击交换按钮切换方向。
6. 使用家谱上的放大、缩小、适应按钮调整视图；画布支持横向和纵向滚动。
7. 点击“导出备份”下载**当前这一张**家谱的 JSON 文件。恢复备份只会**替换当前标签中的家谱**，不会合并，也不影响其他标签；导入前会校验并要求确认。多张家谱请逐张备份。

## 家谱布局

- 按亲子关系分层，父母在子女上方；横向依据父母与子女的位置共同调整，不按随机人物编号排列。子女尽量靠近父母下方，多名子女围绕父母展开。
- 同辈配偶成组排列，兄弟姐妹保持同层并尽量靠近；卡片之间至少留出 30px，画布随布局扩展。复杂姻亲、多配偶或跨辈关系可能无法同时满足所有相邻要求，也不保证消除全部交叉线。
- 布局仅调整显示坐标，不修改成员、亲属关系或已保存的资料；刷新后会根据现有关系重新计算。

## 多张家谱

- 旧版已有资料会显示为“我的家谱”，首次成功保存操作时安全升级，不要求清空旧记录。
- 点击“新建家谱”，填写名称（1–60 字），即创建新的空白标签；原家谱完整保留。点击标签可切换，“重命名”只改当前家谱名称。
- 各家谱的人物、关系和“我是谁”独立保存；不支持跨家谱连线。刷新后保留上次选中的家谱。
- “删除当前家谱”需单独确认，只删除该标签及其中资料，无法撤销，**请先备份**。删除最后一张后仍可重新新建。

空白家谱的“先看看示例家谱”会在当前标签载入并保存 11 位**虚构**人物。体验结束后，可新建另一张家谱录入真实家人，不必删除示例。

## 人物资料

支持姓名、小名／曾用名、性别、出生和去世年月、籍贯／居住城市、职业、备注和照片。

- 日期支持 `1940`、`1940-03`、`1940-03-21`。按公历处理，不支持农历换算。
- 不知道生卒时间时留空，不用填写虚构日期。日期精度不足以判断长幼时，系统显示待确认。
- 照片支持 10 MB 以内的 JPEG、PNG、WebP，自动裁剪并压缩为 256×256 的 JPEG，再存入本机备份。
- 编辑页面允许维护多条父母关系；不同关系类型会影响称呼判断。为孩子新增另一位家长并保存时，若两位尚未关联为配偶，会询问是否同时建立当前配偶关系：“确定”一并保存，“取消”只保存父母关系。已有配偶不会重复添加，未改动父母关系时不会反复询问；历史记录不自动补配偶。
- 配偶连线仅用于当前配偶。历史婚姻和再婚日期暂写在备注中，不进行时间段推算。
- 编辑成员时，可在“兄弟姐妹”中选择已有成员；父母未知也能关联，不会虚构父母。保存后双方显示，图中以同辈虚线连接。再次编辑取消选择可解除直接关联。图例、连线提示、成员资料和关系路径统一显示亲属关系，不附加“手动”标签；内部仍保留关系来源以避免错误推断。
- 共同亲生父母推导的兄弟姐妹仍会自动识别，单独显示在选择框上方；这类关系需修改父母资料才能解除。手动关系不保证同父同母，也不会自动传递到其他成员。
- 删除人物会一起删除相关连线，但保留其他人物，且不能撤销。

## 称呼范围

采用统一的“人物关系图 → 性别／长幼关系链 → 本地称谓词库”查询，不按姓名添加特例。手动兄弟姐妹与共同亲生父母推导的兄弟姐妹使用同一套称谓系统，支持直系祖先后代、伯叔姑舅姨、侄甥、堂表亲、配偶方亲属、堂表亲的配偶、亲家等词库收录的组合。

- 查询区和人物资料同时显示**日常称呼建议**与**完整称谓**。日常建议优先使用熟悉的词库别名，再按性别、辈分、堂表支系和长幼简化远亲叫法，通常为两三个字，不机械截断。例如远房“族兄”可建议叫“堂哥”，“堂舅”可建议叫“舅舅”；原始书面称谓和关系路径完整保留。
- 日常简化不改变亲缘事实，也不表示远亲变成近亲。父辈的伯／叔比较对方与对应父亲的年龄，堂表亲配偶按血亲长幼判断；配偶方远亲可随配偶称呼。祖辈旁系优先使用“伯爷爷”“姑奶奶”等，部分远房祖辈可按辈分建议“爷爷／外公”等。具体叫法仍以当地和家庭习惯为准，不能保证全国通用。
- 日常建议同样保留性别／长幼候选和多路径信息；收养、继亲、未确认的关系、词库覆盖不完整、超限或没有可靠通用短称时，提示“建议称姓名”及原因，不强行编造称谓。
- 查询结果按两个方向分卡展示，宽屏并排、窄屏上下排列；日常建议突出显示，完整称谓、建议说明和可展开路径分层排版。分别计算两个方向，检查所有等长最短路径并合并候选，不再由关系录入顺序随意选择堂亲或表亲。可展开每个方向的路径，核对人物、关系来源和对应称呼；不穷举更长的多重亲缘。
- 根据出生日期区间判断长幼。堂表亲比较本人和堂表亲，而不是父母；涉及配偶时比较对应血亲的年龄。性别或日期不足时列出候选及原因，不要求虚构资料。
- 只沿已经录入的关系查询，不补全家庭事实：兄弟姐妹的家长不一定也是自己的家长，孩子的另一位家长不一定是配偶，配偶的孩子不一定是自己的亲生孩子，兄弟姐妹／配偶关系也不自动传递。遇到这些路径会说明缺少的确认，并保留原始关系链。
- 路径涉及收养或继亲时明确提示，不当作亲生关系。手动兄弟姐妹不区分同父异母／同母异父；称呼按所录兄弟姐妹关系推导，不能据此证明同父同母。
- 为防止复杂家谱卡顿，每个方向最多处理 32 条最短路径，每条最多 12 步、64 组性别／长幼组合。超限、词库未覆盖或只有部分候选被覆盖时明确提示，不冒充唯一确定答案；仍保留人物路径。

称谓词库使用固定版本 [relationship.js 1.2.9](https://github.com/mumuy/relationship)，作者 Haole Zheng，MIT 许可（见安装包中的 `node_modules/relationship.js/LICENSE`）。通过其公开的关系标识词典查询，不调用会归约未确认家庭关系的自然语言推断；常见称呼做显示别名统一。词库包含部分书面称谓，地方习惯可能不同，不能保证资料缺失或任意复杂家庭情况都有唯一称呼。人物资料不会发送给词库作者或外部服务。

首版不包含地方称呼自定义、农历、家谱图片／PDF 导出、账号、多人协作、云同步或权限分享。

## 自定义保存位置

1. 先在电脑上创建私人文件夹，例如 `D:\家谱资料`。
2. 点击页面顶部“保存位置”，粘贴该文件夹的完整绝对路径，再点击“使用此文件夹”。服务账户需要该目录的读写权限；不会自动创建目录。
3. 首次设置会保存**所有标签页的家谱**到 `family-tree-library.json`。随后保存成员、切换／增删家谱等操作均自动写入该文件；重新启动同一项目服务、打开网页时自动读取。
4. 原浏览器数据保留，之后不再同步更新。更改文件夹也会保留旧文件，并将当前完整存档复制到新位置。
5. 目标已有同名文件时，会询问是否**打开现有存档**：不合并、不覆盖，原位置资料仍保留。取消不会切换位置。不要把打开其他存档误认为合并家谱。
6. 保存进行中不能再次提交或更改保存位置，等待保存完成后再操作。

每次文件保存会先将上一版完整内容写入 `family-tree-library.json.bak`，再原子替换主文件；主文件替换失败时会还原保存前的备份。若备份还原也失败，错误提示会指出保留下来的恢复文件，请勿删除它，先停服务并复制保管后再恢复。`.bak` 只有上一版，并非完整历史；请另做定期备份。顶部“导出备份／恢复备份”仍只操作**当前一张家谱**，不能用于恢复整个多家谱文件。

保存路径记录在项目目录的 `.family-tree-storage.json`，服务重启后依靠它定位存档，请勿随意删除。异常情况下：

- 文件丢失／损坏、磁盘不可用或权限不足时，会显示错误并停止对应写入，不会静默改回浏览器保存。保存失败的成员表单保留，未成功提示前不要关闭；网络中断时应刷新核对是否已落盘。
- 恢复 `.bak`：先停止所有家谱服务，将主文件、备份和配置另行复制保管；确认备份正确后，再用备份副本替换同目录主文件，重新启动并刷新。不要直接覆盖唯一一份原始资料。
- 异常退出可能留下配置旁的 `.family-tree-storage.json.lock`。只有确认所有家谱服务已停止后才可删除这个锁文件，再重启；不要删除存档或配置。
- 不要在应用运行时用其他程序同时编辑这些文件。应用会检查文件版本，但不是数据库事务，也不保证拦截任意外部程序最后瞬间的修改。若使用云同步或网络共享文件夹，其同步和权限由该软件负责，应用不提供跨设备合并。
- 更新到本版本后，先保存旧页面中未提交的编辑，再关闭旧标签并刷新。旧版已打开的页面不会自动识别新保存位置。

## 保存与隐私

- 未设置文件夹时，以 JSON 保存在浏览器 `localStorage` 的 `family-tree.v1` 键下。该键存储 version 2 的多家谱集合，兼容旧单家谱；导出和恢复使用原 version 1 单家谱格式。迁移沿用同一存储键与写锁。
- **持久化不等于可靠的长期备份。** 浏览器模式下清理数据、隐私模式结束或卸载浏览器会丢失资料；文件模式下删除文件、磁盘故障也会丢失资料。
- 存档与备份含完整人物信息和照片，**没有加密**；有浏览器或文件访问权限的人可能读取它们，请选择可信位置并另行备份。
- 本机服务仅提供白名单静态文件和同源保存接口，只接受本机 Host、同源请求及专用请求头，不提供跨域访问。新增接口读写所选目录中的固定存档、备份及项目配置，不提供任意文件下载。称谓词库从本机加载，不请求外部脚本、字体、分析服务或照片。
- 恢复损坏或错误版本的备份不会覆盖现有家谱；空间不足或保存失败时显示错误，不假装保存成功。
- 浏览器存档损坏时，可用“导出备份”下载浏览器中的**全部原始存档**供抢救；该文件未修复，不能直接作为单谱备份恢复。它不是磁盘模式的最新副本；磁盘存档请直接保管原文件和 `.bak`。
- 浏览器模式下，其他标签更新会提示刷新，保存使用 Web Locks 并重新确认服务未切换保存位置。使用支持 Web Locks 的新版浏览器（如 Chrome、Edge、Firefox、Safari）通过本机地址打开，不支持时不会保存或迁移。文件模式使用服务端写锁与版本检查；陈旧页面保存会报错，需要刷新再编辑，不自动合并。这不是多人协作协议。
- 打开成员编辑框后，若家谱切换或已保存内容发生变化，旧编辑框不能保存或删除成员；请关闭后重新打开，避免误改另一张家谱中的同编号人物。
- 每张家谱最多 500 位人物、2000 条关系；单张备份和全部家谱存档合计均不得超过 15 MB（UTF-8 字节）。浏览器实际可用容量通常更小，照片过多时应减少照片，或先备份再删除不需要的家谱。容量不足的保存与迁移不会替换原存档。

## 测试

```powershell
Set-Location D:\CjlFile\family-tree
node --test
```

测试覆盖双向称呼、父系／母系和长幼不明、特殊关系、不连通人物、备份校验、错误日期、关系循环、删除关系清理、存储异常、布局和静态服务边界；包括手动兄弟姐妹的校验与同层布局，以及多家谱的旧数据迁移、隔离、增删切换、总容量限制和陈旧页面写入保护。编辑回归测试运行实际的编辑及保存处理函数，验证等待写锁期间切换／更新家谱后，旧表单不能保存或删除成员，正常编辑仍可用。

通用称谓回归包括堂表亲及配偶的长幼锚点、三代直系、姻亲及逆向称呼、多条等长路径、未知性别、未确认家庭关系、路径／组合超限，以及 500 人共享家长的查询。称谓变更不改变存储格式。

浏览器回归检查：添加 → 设置本人 → 添加父母关系 → 查询 → 编辑 → 刷新 → 照片 → 备份恢复 → 删除。检查手机窄屏不产生整页横向滚动，错误日期／错误备份不改变已保存内容。

新增功能回归：在独立测试网址上载入旧单谱，添加／解除手动兄弟姐妹；新建、重命名、切换两张家谱，检查同编号人物和本人视角互不影响；验证单谱恢复／导出、取消删除、删除最后一张后重新新建。读取备份期间切换家谱、模拟存储配额不足、另一页面修改后提交旧编辑，均不得覆盖新记录。检查 390px 窄屏和 60 字长名称。命名使用页面内对话框，不依赖内置浏览器不支持的 `prompt()`。

文件保存回归使用独立临时目录及真实 HTTP 服务，验证多家谱迁移、服务重启读取、上版备份、已有目标确认、并发与陈旧写入、缺失／损坏文件、备份写入失败、规范化后容量限制和请求来源校验。编辑器回归验证文件模式不修改浏览器副本、保存失败保留表单、服务读取失败不降级，以及迁移期间浏览器更新不会被遗漏。
